曼德博集合与图像

六行数学，一张无限复杂的图

难度 ★★★☆☆ 建议 5–8 小时 主线：把程序变成产品 阶段四

本板块会用到的新知识点

最后一个项目。你将第一次写一个「输出不是文字」的程序——而这个差别，比它看起来重要得多。

  • 二进制文件输出　std::ofstream out(path, std::ios::binary); 配合 out.put(字节) 以前写的是给人看的文本，这次写的是给程序看的字节。一旦掌握了这一招，你的程序就能生成图片、音频、模型文件—— 它开始产出「作品」而不只是「结果」。
  • BMP 文件格式　一个非常老、非常直白的图片格式：54 字节文件头 + 调色板 + 像素数据。 它是最好的「文件不过是一串字节」的教材。
  • 小端序与字节拆装　形如 out.put(value & 0xFF); value >>= 8; 一个 int 是 4 个字节，写进文件时需要决定谁先谁后。BMP 规定低位字节在前。
  • 坐标映射　cr = -2.20 + 3.00 * x / WIDTH 把「第 x 列像素」翻译成「复平面上的某个数」。可视化的第一步永远是这件事：把屏幕坐标翻译成数据坐标。 将来你画损失曲线、画决策边界，用的都是同一个映射。
  • 一维缓冲区当二维用　gray[y * WIDTH + x] 内存在物理上永远是一条线。项目 07 的矩阵内部也是这么存的，这里你自己动手算一次下标，感受会更实在。

一、这件事在真实世界里长什么样

取一个复数 c，令 z 从 0 开始， 反复做同一件小事：z = z² + c。

有的 c 会让 z 越跑越远，有的会让它老老实实待在一个小圈子里。 把「待得住」的那些 c 涂黑，就得到了曼德博集合。

规则就这么一句话。可当你把它画出来——你会看到一个边缘无限复杂的图形： 无论放大多少倍，新的细节都会继续冒出来，而且每一处都隐约带着整个图形的影子。

这个项目想让你体会的是：程序的产出，可以不只是屏幕上的几行数字。 你的代码第一次会生成一个文件，这个文件可以被别的软件打开、可以发给别人、可以印在纸上。 这就是「产品」和「作业」的区别。

二、任务拆解：三关

  1. 先算一个点

    写一个函数：给定 c，迭代 z = z² + c 最多 200 次， 每次检查 |z|² > 4 就提前返回「第几次跑掉的」。 先在 main 里手工试几个 c，比如 (0,0)、(1,1)、(-1,0)，看它们的逃逸次数差多少。

  2. 把整张画面算出来

    开一个 480×320 的 vector<unsigned char>， 对每个像素：先把行列号映射成复平面的坐标，算出逃逸时间，再映射成 0–255 的灰度，存进缓冲区。 在终端用字符画先看一眼——只要形状对了，后面就都好办。

  3. 写成一张真正的图片

    按 BMP 的格式写文件：14 字节文件头 + 40 字节信息头 + 256 级灰度调色板 + 像素数据。 三个必须记住的细节：每行字节数补齐到 4 的倍数、像素自下而上存储、写完用图片查看器打开它。

这段代码美在哪里
  1. 极致的投入产出比。 整个图形的数学核心只有两行： zr = zr*zr - zi*zi + cr; 和 zi = 2*zr*zi + ci;。 用最少的数学，生产出无限复杂的结构——这是数学之美，被你的代码原样搬运到了屏幕上。
  2. squareAndAdd 这个函数，把「复数平方加 c」变成了一个动词。 它内部明明有四行运算，但调用处只写 squareAndAdd(zr, zi, cr, ci);， 读起来就是它名字说的那件事。给一段操作起一个准确的名字，是抽象的开始。
  3. 整数除法的顺序被刻意安排过。 (i * 255) / MAX_ITER—— 先乘后除，是为了不让整数除法过早地把结果截断成 0。 这种细节看起来很小，但它决定了图像是平滑过渡还是一团死黑。
  4. 文件写入被拆成了 writeInt / writeShort 两个小函数。 BMP 头有十几个字段要写，如果不拆，主函数里会出现十几行一模一样的 out.put(...)。 拆完之后，文件头的结构一眼就能对上 BMP 的文档。
  5. 同一个缓冲区，喂给了两个完全不同的输出。 saveBmp() 把它变成图片，printPreview() 把它变成字符画。 「计算一次、呈现多次」——把数据的产生和数据的展示分开，是一个值得记住的架构习惯。
  6. 它的产物可以拿给别人看。 这是本手册十个项目里，唯一一个能直接「展示」的作品。 而这，正是「产品落地」最朴素的定义。
常见陷阱
  • BMP 每一行的字节数必须是 4 的倍数。 480 刚好是 4 的倍数，所以看起来没问题； 但你一旦把宽度改成 481，图片就会歪斜——因为少补了那几个填充字节。这是格式规范，不是可以省略的优化。
  • BMP 的像素是自下而上存储的。 忘了这件事，得到的图片会上下颠倒。 写循环时那个 for (int y = h - 1; y >= 0; --y) 就是干这个的。
  • 8 位灰度图必须带那 256 级调色板。漏掉它，图片查看器会打不开或者显示成乱码。
  • 迭代上限 MAX_ITER 太小，图形边缘会很粗糙；太大则计算变慢。 这又是一次「精度与速度」的权衡，和项目 08 里调学习率是同一类问题。
  • 直接开 -O0 编译并跑 480×320，你会明显感觉到等待。 这可能是你第一次真切地意识到：算法一样，快慢可以差很多倍。
进阶挑战
  • 放大一个区域。 把复平面的范围改成 [-0.75, -0.73] × [0.09, 0.11]， 并把迭代上限提到 1000。你会亲眼看到自相似性——一个局部里藏着整个图形的样子。
  • 把 c 固定、把初始的 z 设为每个像素的坐标，得到的是朱利亚集合。 只改两行代码，又是一整个家族的新图形。
  • 既然要写图片了，那就试试 24 位彩色 BMP：调色板那一段去掉，每个像素写三个字节。 然后按逃逸时间给不同的通道不同的强度，做一张有颜色的图——你会发现颜色的数学和形状的数学一样有趣。
  • 用 Python 三行代码读一下你生成的这个文件： import imageio; img = imageio.imread('mandelbrot.bmp'); imageio.imwrite('m.png', img)。 这是你的 C++ 与未来的 Python 第一次握手的时刻。
  • 把这张图接到项目 03 的网格上：读取图片的像素亮度，用不同的字符打印出来。 两个项目一拼接，你就得到了一个「终端图片查看器」。

APPENDIX A

让代码优雅的十条习惯

这是整本手册里唯一不讲新知识的一节，但也可能是最值钱的一节。下面十条，每一条都能在你写的每一个程序里兑现。

#习惯为什么
1名字要能被读出来 averageOf 比 avg 好，avg 比 a 好。 代码是写给人读的，只是顺便让机器执行。变量名多打三个字母，未来能省半小时。
2一个函数只做一件事 如果你需要用「和」来介绍一个函数（「这个函数读取并排序并打印」），它就该被拆成三个。 能一句话说清楚的函数，才配拥有一个好名字。
3能加 const 就加 const const 是写给编译器看的承诺，它会在你违约时报错。 把「我不会改这个数据」变成编译期能检查的事实，等于免费雇了一个审查员。
4数据与逻辑分开 结构体只装数据，函数只做动作。项目 01 到 10 全都遵循这一条。 分开之后，换数据源不用改逻辑，改逻辑不用动数据。
5不要重复自己 当你准备第三次复制粘贴同一段代码时，停下来，把它抽成一个函数。 三次是经验法则：第一次可以随便写，第二次忍一忍，第三次必须重构。
6边界要挡住 空容器、越界下标、除以零、打不开的文件、维度不匹配的矩阵。 程序崩溃的地方，九成在边界上。
7出错要出声 返回 false 或者打一行 std::cerr，比默默算出一个错误答案好一万倍。 沉默的 bug 是最贵的 bug。
8让代码的形状对应问题的形状 项目 05 里，加减法调用乘除法，所以乘除先算——优先级被写进了代码的结构里。 项目 03 里，八个方向变成了一张表。当代码的结构和问题的结构对上时，读代码就不需要注释了。
9注释写「为什么」，不写「是什么」 // i 加一 这种注释是噪音； // 每行补齐到 4 字节，这是 BMP 的格式要求 才是真注释。 代码已经说了「是什么」，注释要说的是代码说不出的那部分。
10永远带着 -Wall 编译 编译器免费的警告，往往指向一个你还没遇到的 bug。 一个零警告的程序，不一定是对的；但一个满是警告的程序，大概率有问题。

这十条里没有一条是「聪明」的技巧，全都是「克制」的功夫。
写代码的功力，到最后拼的不是你知道多少花招，而是你能忍住不写多少花招。

APPENDIX B

编译、调试与求助

B.1 最常用的几条命令

命令作用
g++ -std=c++14 -Wall main.cpp -o main最常用的编译方式，本手册全程使用
g++ -std=c++14 -Wall -O2 main.cpp -o main打开优化。项目 10 这种计算量大的程序会快很多
g++ -std=c++14 -Wall -g main.cpp -o main带上调试信息，配合 gdb 使用
./main ／ main.exe运行。Windows 下是后者，Linux / macOS / Git Bash 下是前者
./main < input.txt把文件当成键盘输入喂给程序，方便反复测试
./main > output.txt把输出存进文件，方便对比和粘贴
g++ -std=c++14 -Wall -fsyntax-only main.cpp只检查语法，不生成可执行文件，改代码时用得很顺手

B.2 八个最常见的错误信息，以及它们的真实含义

编译器说翻译成人话
expected ';' before '}' token上一行末尾漏了分号。看报错行号的上一行。
'xxx' was not declared in this scope这个名字你没定义、或者拼错了、或者忘了 #include 对应的头文件。
undefined reference to 'yyy'编译通过了但链接失败。函数只有声明没有定义，或者多个文件没一起编译。
no matching function for call to ...参数类型或个数对不上。检查你有没有传错顺序、或者该传引用却传了值。
passing 'const X' as 'this' argument discards qualifiers你在一个 const 对象上调用了非 const 成员函数。给那个成员函数加个 const 就好了。
comparison between signed and unsigned integer expressions警告，不是错误。int 和 size() 比较了，加个 static_cast<int>。
Segmentation fault ／ 程序直接闪退访问了不属于你的内存：下标越界、用了空指针、返回了局部变量的引用。
ld returned 1 exit status链接失败。Windows 上最常见的原因：上一次运行的程序还开着，文件被占用，关掉它再编译。

B.3 调试三招

  1. 打印出来看

    在关键位置加一行 std::cerr << "i = " << i << "\n";。 用 cerr 而不是 cout，这样即使你用 > 重定向了输出， 调试信息依然会显示在屏幕上。这是最原始也最有效的办法，专业程序员每天都在用。

  2. 把问题缩小

    程序在 100 个数据上错了，就改成 3 个数据，手工把每一步的结果算一遍，和程序的输出逐个对比。 能稳定复现的小例子，比一百行日志管用。

  3. 怀疑「刚才改的那一行」

    如果代码五分钟前还是好的，那么错误几乎一定在你刚才的改动里。 先回退，再一位一位地改回来，错误就会自己冒出来。

卡住的时候，这样求助

不管是问同学、问老师还是问 AI，一段好的提问应该包含四样东西：

  1. 我想做什么（一句话说清目标）
  2. 我写了什么（贴出相关的最小代码片段，不要贴整个文件）
  3. 发生了什么（完整的报错信息，包括行号；或实际输出与预期输出的对比）
  4. 我试过什么（这一步最能让对方认真回答你）

把问题描述清楚的过程，本身就是一半的解题过程。很多时候，你在写第 3 条的时候就已经找到答案了。

APPENDIX C

从这里走向 Python 与人工智能

C.1 先说一个可能让你意外的事实

你说你之后的学习重点是 Python，而写这份手册用的是 C++。这两件事看起来有点别扭，其实一点都不矛盾——

你在这十个项目里真正学到的东西，几乎全都不是 C++ 的。
「把数据和对数据的操作分开」「一个函数只做一件事」「用方向数组消灭重复的 if」 「先取对数再求和」「训练和预测要分开」——这些是编程的思想，换到 Python、换到任何语言，它们一个字都不用改。

语言会变，工具会变，但你在这十个项目里建立起来的「面对一个空白文件时知道从哪下手的底气」，是会一直带着走的。

C.2 你现在手里有什么

能力它是从哪来的在 Python 里怎么用
用合适的数据结构装数据项目 01–03 的 vector / map / 二维数组list / dict / 嵌套 list，一一对应
把大问题拆成小函数每一个项目def 函数，思路完全一样

C.3 如果还想再深入 C++

按你的专业方向，我不建议你现在花太多时间在 C++ 的高级特性上。但有三个方向值得留意：

  • STL 算法库（<algorithm>）：find_if、count_if、transform、accumulate。 它们能让你的代码再短一半，而且和你将来要用的 pandas 风格非常接近。
  • 把程序拆成多个文件：.h 放声明、.cpp 放实现。 项目 07 的进阶挑战里提过。这是从「写脚本」走向「做工程」的第一步。
  • 性能意识：同一段算法，写法的不同可以让它快十倍。项目 10 的 -O2 和项目 06 的 alpha-beta 剪枝， 已经让你摸到这件事了。人工智能里，这一条非常值钱。

至于模板元编程、移动语义、智能指针、并发、C++20 的新特性——先放着。等你真的遇到需要它们的问题时再学，效率会高十倍。

C.4 给大一人工智能专业学生的一条路线

  1. 数学，现在就开始，一天都不要等

    线性代数、概率论与数理统计、微积分。人工智能的本质是这三门数学，编程只是把它们变成可执行的形式。 项目 07 的矩阵乘法就是线性代数，项目 09 的贝叶斯就是概率论，项目 08 的「错一点改一点」就是微积分里的梯度。 数学课上听过的每一个概念，你都应该想一想：这个东西用代码怎么写？

  2. 数据结构与算法

    你在这本手册里已经摸到了队列、搜索、递归、哈希表。接下来系统地学一遍：链表、栈、树、堆、图、动态规划。 这是你和「只会调库的人」之间的差距所在。

  3. Python 与它的科学计算栈

    语法一周就能学完（你已经有编程基础了，会非常快）。真正要花时间的是三样东西： numpy（把项目 07 的矩阵类换成它，速度差几百倍）、 pandas（把项目 02 的统计换成它，三行顶你一百行）、 matplotlib（把项目 10 的位图换成它，一行出图）。

    一个高效的学法：把这本手册里的项目，用 Python 重写一遍。 你已经知道正确答案是什么了，所以可以全力关注「这门新语言是怎么表达的」。 词频统计、矩阵乘法、感知机、朴素贝叶斯——四个项目重写下来，Python 你就掌握了。

  4. 然后是 PyTorch，以及真正的机器学习

    到那个时候你会发现，项目 08 里那三个 double 的感知机，和 PyTorch 里的一个大模型，骨架是一样的： 定义模型、前向计算、算损失、反向传播、更新参数。你只是把参数从三个变成了几十亿个。

最后一句话

这本手册的十个项目，没有一个是为了考试准备的。它们全部都在做同一件事： 让你在「想法」和「能跑起来的东西」之间，建立一条通畅的路。

这条路修好之后，你学什么语言、做什么方向，都只是换一辆车而已。
