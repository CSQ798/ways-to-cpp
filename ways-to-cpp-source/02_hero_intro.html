BEFORE YOU START

怎么用这本手册

你说过一句话：语法都学过，但一到算法层面就无从下手。这不是你的问题，这是所有只做课后题的人都会遇到的坎。 课后题的形式是「输入 A，输出 B，用一个循环解决」，而真实程序的形式是「有一堆数据，我该怎么摆放它们， 该派哪些函数去处理，出错时谁来兜底」。这两件事用的是同一门语言，却是两种完全不同的思维方式。

所以这本手册的每一个项目，都按照同一套结构来写，你按这个顺序读、按这个顺序做，效果最好：

板块它是干什么用的
项目背景先告诉你这件事在真实世界里长什么样。你会知道自己在造什么，而不是在凑一个循环。
本板块新知识点每个项目开头都会先列出没学过的内容。看到不认识的词不要慌，那是接下来要解决的问题的答案。
任务拆解把一个项目切成 Lv1 / Lv2 / Lv3 三关。请务必先自己动手写，卡住了再看参考实现。
参考实现完整源码 + 真实运行结果。代码可以在 ways-to-cpp-code/ 里找到，直接编译就能跑。
美在哪里逐条讲解这段代码为什么这样写更好看、更好改。这是本手册最想给你的东西。
常见陷阱 / 进阶挑战前者帮你少走弯路，后者给你继续往前走的方向。

三条硬规矩

  1. 先关掉参考实现，自己写四十分钟。哪怕写得很丑、编译不过、逻辑全错，那四十分钟的价值也大于直接抄一遍。
  2. 每一关都要真的编译、真的运行。看懂和写出来之间，隔着一次 error: expected ';'。
  3. 动手改。把示例数据换成你自己的、把 10 改成 100、把升序改成降序。你对代码的掌控感是改出来的。
编译与运行环境

本手册所有代码都在 C++11 / C++14 标准下编写，任何一个现代编译器都能直接通过。以 MinGW 的 g++ 为例：

g++ -std=c++14 -Wall p01_grade_analyzer.cpp -o p01

./p01          # 在 Linux / macOS / Git Bash 下
p01.exe        # 在 Windows 的 cmd 或 PowerShell 下

-Wall 的意思是「把该提醒我的都提醒我」。初学者最该养成的习惯之一，就是永远带着它编译—— 编译器是你身边最便宜、最诚实的老师。

关于「新知识」的分寸

你希望少碰语言的高级特性，这个尺度我按下面的标准把握：

  • 收进来的：标准库中真正日常的工具（vector、map、sort、文件流、class 与运算符重载），以及算法本身的思想（搜索、递归、概率）。它们是「做事要用的」，不是「考试要考的」。
  • 挡在外面的：模板元编程、移动语义与右值引用、智能指针、lambda 的进阶用法、多线程、编译期计算、C++20 概念等。这些是有价值的，但对你当前的阶段而言，投入产出比很低，而且 Python 与 AI 的路线用不上它们。

新知识点总表

下面这张表是本手册的「新东西清单」。左边是知识点，中间告诉你它为了解决什么问题才出现， 右边一列是它在 Python 里的近亲——你是人工智能专业的学生，这条路迟早要走到 Python 上去， 提前建立这种对应关系，将来迁移会轻松得多。

项目新知识点它为什么存在Python 里的对应物
01const 与 const 引用告诉编译器也告诉读者：这个数据到此为止，不许改约定俗成的常量命名

04std::pair 与前驱表把两个值绑成一个、并记录「我是从哪来的」，用来复原路径tuple / 字典记录父节点

07const 成员函数承诺「这个函数不会改动对象」，编译器替你把关没有直接对应，靠自觉

09概率取对数把连乘变成连加，避免小概率相乘变成 0np.log 累加
