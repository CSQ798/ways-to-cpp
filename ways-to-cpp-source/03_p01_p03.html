01

学生成绩分析器

把一堆分数交给数据自己去排队

难度 ★★☆☆☆ 建议 3–5 小时 主线：数据组织 阶段一

本板块会用到的新知识点

下面这些你还没学过。不用提前去查，读到需要它们的地方，回来对一眼就行。

  • const 引用参数　形如 const std::vector<Student>&。一个 & 让函数不用拷贝整份数据，一个 const 保证函数不会偷偷改你的东西。
  • std::vector　需要 #include <vector>。长度可以变的数组。你以前写 int a[100]，是猜一个足够大的数；vector 让数组自己长大。
  • 范围 for　形如 for (const Student& s : students)。「对 students 里的每一个 s」，不必再写 i = 0; i < n; ++i。
  • std::sort 与比较函数　需要 #include <algorithm>。标准库自带的排序，比手写冒泡快得多；你只需告诉它「谁该排前面」。
  • static_cast　形如 static_cast<double>(n)。明确地做一次类型转换，比 C 风格的 (double)n 更醒目、更安全。

一、这件事在真实世界里长什么样

每学期期末，老师手里都有一张成绩表。他想要的东西会不断变：今天想知道平均分，明天想排出名次， 后天想看看「这个班是不是两极分化」——那是标准差要回答的问题；再过两天教务又要按等级统计人数。

如果你把这些需求全塞进 main 里，写成一段长长的循环，那么每来一个新需求，你都要重新读一遍那段代码， 小心翼翼地不要碰坏别的地方。这个项目要教你的，就是把「数据」和「对数据的操作」分开。 分开了之后，加一个需求，只是多写一个函数而已。

二、任务拆解：三关

  1. 先把数据装起来

    定义 struct Student { std::string name; int score; };，用你在数组那一章学过的写法， 造 8 个学生的固定数组，打印平均分和最高分的同学。这一关只用你已经会的东西，目的是热身。

  2. 把动作拆成函数

    把「平均分」「最高分」「标准差」各写成一个独立函数。函数参数用 const std::vector<Student>&， 容器改用 std::vector。检验标准：main 里只剩下「准备数据」和「调用函数」两种语句。

  3. 让它能排名、能评级

    用 std::sort 把学生按分数从高到低排好，输出一张带序号、姓名、分数、等级的成绩单。 排序规则单独写成一个函数，名字要能读懂。

  1. 结构体只装数据，函数只做动作。 Student 里一行逻辑都没有，averageOf 里一行存储都没有。 这种「各自的活各自干」的分工，是后面所有项目的基础。
  2. 一个 const 引用，同时买到两样东西。 & 免去拷贝整份数据的开销，const 让「我不会改你」这句话变成编译器能验证的事实。 读代码的人看到这个签名，就再也不用担心 averageOf 会动他的数据。
  3. 排序规则有了名字。 比较一下这两种写法：sort(v.begin(), v.end(), [](auto& a, auto& b){return a.score>b.score;}) 和 sort(v.begin(), v.end(), higherScoreFirst)。 后者读起来就是一句英文，而且这个规则可以在别处复用、可以单独测试。
  4. 函数是「纯」的。 averageOf 除了传入的容器，不依赖任何外部状态。 这样的函数可以被随手调用一万次，结果永远一样——这是可靠代码最重要的性质。
  5. 换数据源，不用改逻辑。 把 main 里那段演示数据换成 cin 读入， 上面五个函数一行都不用动。这就是「解耦」在真实项目里的回报。
常见陷阱
  • students.size() 返回的是无符号整数，直接和 int i 比较，编译器会警告「有符号与无符号比较」。 本手册统一写成 static_cast<int>(students.size())。
  • 比较函数里千万别写 >=。std::sort 要求「严格弱序」， 写 >= 会在某些数据下越界崩溃——这是个非常经典的坑。
  • 空容器求平均会除以 0。所以 averageOf 第一行就先挡住 empty() 的情况。
  • 浮点输出不加 std::setprecision 会打印出 75.375 这样的默认六位有效数字，也可能是 1e+06。 要显示小数，记得 <iomanip> 里的 std::fixed << std::setprecision(2)。
进阶挑战
  • 让程序从 scores.txt 读入成绩（每行「姓名 分数」）。读文件的方法在项目 02 会讲，你可以先自己试试。
  • 再加一套排序：「按姓名升序」。你会发现排序规则函数可以随便换，其余代码纹丝不动。
  • 求出中位数，并比较它和平均分的差距。差距大，说明分数分布是偏的——这是真实数据分析里最常用的第一眼判断。
  • 统计每个等级有几个人，并且用 # 画一个横向条形图。想想看：这个「等级 → 人数」的对应关系，用什么容器存最自然？
02

英文词频统计器

让文件和字典替你做苦力

难度 ★★☆☆☆ 建议 3–5 小时 主线：查表与持久化 阶段一

本板块会用到的新知识点

这个项目会引入两个你以后几乎天天要用的东西：map 和文件。

  • std::map　需要 #include <map>。「键 → 值」的对应表。 它的下标 counter[word] 有一个非常贴心的性质：键不存在时会自动创建一个值为 0 的条目， 所以「数数」这个动作被压缩成了一行 ++counter[w]。
  • 文件流　std::ifstream 读、std::ofstream 写，需要 #include <fstream>。 让数据活过这一次运行。用法和 cin/cout 几乎一模一样，只是把「屏幕」换成了「文件」。
  • std::getline　需要 #include <string>。一次读一整行。注意：cin >> s 遇到空格就停， 而 getline 会连空格一起读进来——读文本时这个区别至关重要。
  • std::isalpha / std::tolower　需要 #include <cctype>。判断「是不是字母」、把大写变小写。 标准库早就写好了，别自己写 if (c >= 'A' && c <= 'Z')。
  • typedef / using 起别名　形如 typedef std::map<std::string,int> Counter;。 把一长串类型名缩写成一个词，读代码时脑子轻松很多。
  • std::pair　需要 #include <utility>。把「词」和「次数」捆成一件东西， 这样它们才能一起被排序。.first 是第一个，.second 是第二个。

一、这件事在真实世界里长什么样

「数一篇文章里每个词出现了多少次」听起来像课堂练习，但它其实是搜索引擎、文本分类、语言模型的第一步。 你要做的搜索引擎，需要知道哪些词重要；你要做的垃圾邮件过滤器（项目 09），需要知道哪些词可疑； 你要做的情感分析，需要知道「好」和「差」各出现了几次。

而「查表」这件事的通用解法，就是 map。学会它之后，你会发现一大类问题都变成了同一道题。

二、任务拆解：三关

  1. 先把文本切干净

    写一个函数，输入一整段文本，输出一串「干净的单词」：去掉标点、统一小写、连续字母才算一个词。 先别管统计，把切分这一个动作做对、做稳。提示：边扫边攒，遇到非字母就把攒好的词交出去。

  2. 数数，然后按次数排名

    用 map 统计词频（这一步只有三行）。然后你会发现 map 是按「键」排的， 而你要按「值」排——所以把它搬进 vector<std::pair<std::string,int>>，再用项目 01 学过的 std::sort。

  3. 让它读真正的文件

    把文本存成 sample.txt，用 ifstream + getline 一次一行读进来。 再加一点贴心设计：文件不存在时给出友好提示，而不是让程序默默输出一堆 0。

  1. 「数数」被压缩成了一行。 换成数组的写法，你要先判断这个词出现过没有、出现在哪个位置、再累加。 ++counter[w] 之所以能成立，是因为 map 的下标访问会在键不存在时自动建一个 0。 好的数据结构，能把算法「吃掉」。
  2. 函数按照「一件事」来切。 splitWords 只负责切，countWords 只负责数， readAll 只负责读。三个函数分别可以单独测试，也分别可以单独替换。
  3. 排序规则考虑了「平局」。 只按次数排序时，次数相同的词顺序是不确定的，每次运行可能不一样。 加一句「次数相同按字典序」，输出就完全稳定了。稳定性是工程素养，不是小事。
  4. 把字符统一成小写再统计。 否则 It 和 it 会被算成两个词。 真实数据永远是脏的，清洗要在最前面做。
  5. 写文件之前先检查文件是否存在。 一个看起来无关紧要的小判断，避免了「把用户自己的文件覆盖掉」这种灾难。
常见陷阱
  • cin >> word 会在空格处停下，getline 不会。 混用这两者时，前一个留下的换行符会被后一个立刻读走，导致「少读一行」。这是初学者最常撞的墙。
  • std::tolower 的参数必须是 unsigned char 转过来的值。 直接传负数字符在某些平台上会越界崩溃，所以要写 std::tolower(static_cast<unsigned char>(c))。
  • counter[w] 只能用在「非 const」的 map 上。如果你把 map 声明为 const， 就必须用 .find() 来查（项目 09 会这么做）。
  • 忘了 current.clear() 或者忘了最后那个词——切词函数里最容易漏掉的就是这两个点。
进阶挑战
  • 支持中文文本。中文字符是「多字节」的，一个汉字在 UTF-8 里占三个字节——你会直观地看到「字符」和「字节」的区别， 以及为什么处理中文比英文麻烦。
  • 统计「二元组」：把相邻两个词当成一个单位来数（比如 of the）。 这是语言模型最原始的形态，也只需要把 map 的键换成 pair。
  • 加一个「停用词表」：the、a、of 这类词不统计。你会发现前几名立刻换人了。
  • 让程序接受命令行参数指定文件名。C++ 里 main(int argc, char* argv[]) 就是干这个的。
03

康威生命游戏

三个简洁的规则，一个会自己生长的世界

难度 ★★★☆☆ 建议 4–6 小时 主线：二维数据与规则 阶段一

本板块会用到的新知识点

这个项目会教你两件影响深远的事：二维数据怎么摆，以及怎样把「重复的代码」变成「数据」。

  • 二维 vector　形如 std::vector<std::vector<int>>。 「装着一行行数组的数组」。网格、棋盘、图像、矩阵，全都是这个形状。
  • using 类型别名　using Grid = std::vector<std::vector<int>>; 写完这一行，后面所有函数签名里就只出现 Grid 一个词，读起来清爽得多。
  • 方向数组　形如 const int DR[8] = {-1,-1,-1,0,0,1,1,1}; 把「八个方向」变成两张静态表。八个方向不再需要八段 if，而是一个循环。这是算法里最常见的一次「用数据消灭代码」。
  • 双缓冲更新　读旧表 current，写新表 next。 所有格子必须同时更新。如果你直接在原表上改，后面算的格子会读到已经被改过的邻居，结果全乱。
  • const 语义的深入　liveNeighbors(const Grid& g, ...) 传进来只读的用 const Grid&，要改的用 Grid&。 看函数签名就知道它会不会动我的数据，这是 C++ 独有的表达力。

一、这件事在真实世界里长什么样

1970 年，数学家约翰·康威设计了一个「零玩家游戏」：一个方格世界里，每个格子要么活着要么死了，下一代怎么变，只看它周围八个邻居里有几个活人。

规则只有三条：邻居少于 2 个，孤单而死；邻居是 2 或 3 个，继续活着；邻居多于 3 个，拥挤而死；死格子周围正好 3 个活人，就复活。

就这么三条规则，却能长出滑翔机、振荡子、甚至能计算的逻辑门。这个项目真正的价值不在游戏本身， 而在于你第一次写出「按规则演化」的程序结构——它和森林火灾模拟、疫情传播模型、元胞自动机、乃至卷积神经网络里的滑窗操作，是同一副骨架。

二、任务拆解：三关

  1. 先把世界画出来

    造一个 14 行 34 列的二维网格，把「滑翔机」这个经典图案摆进去，写一个函数把它打印出来。 先不管演化，能看见就是胜利。

  2. 数邻居，然后算下一代

    写 liveNeighbors()，注意四条边界都要检查越界。 然后写 nextGeneration()：它接收旧网格，返回一张全新的网格。 关键：不要在原网格上直接改。

  3. 让世界动起来

    把「打印 → 演化」放进一个循环，连续输出若干代。观察滑翔机每四代向右下移动一格—— 当你亲眼看到它动起来的时候，你才算真正理解了这个程序。

这段代码美在哪里
  1. 八个方向变成了两张表。 不用方向数组的写法，liveNeighbors 里会有八段几乎一样的 if (r-1 >= 0 && c-1 >= 0) count += g[r-1][c-1];。 用了方向数组之后只剩五行。当你想复制粘贴第三遍的时候，就该停下来想想：这段东西能不能变成数据？
  2. 「读旧、写新」是一次重要的思维升级。 让 nextGeneration 接收一个 const 引用、 返回一个全新的 Grid，从函数签名上就杜绝了「边算边改」的错误。函数的形状本身在保护你。
  3. 规则写成了和规则本身一样的形状。 看这两个三目运算符： next[r][c] = (n == 2 || n == 3) ? 1 : 0;。它读起来几乎就是「邻居是二或三就活」这句话本身。 代码和意图之间没有多余的翻译层，这就是优雅。
  4. 参数名说明了用途。 placeGlider(Grid& g, int top, int left) 里的 top 和 left， 比 x、y 或 a、b 好懂得多。命名的功夫，就是替未来的自己省时间。
常见陷阱
  • 最常见的错误：边遍历边修改。 症状是图案会在几代之内莫名其妙地死光。原因就是后面的格子读到了已经被改写的邻居。 解法只有一个：写进另一张表。
  • 二维 vector 的初始化不能写 Grid g(rows, cols)，那是「rows 个值为 cols 的元素」。 正确的是 Grid(rows, std::vector<int>(cols, 0))。
  • 边界忘记检查会读到别的行——C++ 不会报错，只会算出荒唐的结果。这类错误最耗时间，所以越界判断要写得像条件反射。
  • 想让它「动」起来需要 <thread> 和 <chrono> 里的睡眠函数。 这两个头文件在某些老版本的 Windows 编译环境下支持不佳，所以本手册的版本故意不加入动画—— 先保证代码在任何机器上都能跑，再考虑锦上添花。
进阶挑战
  • 把边界从「死墙」改成「环绕」：第 0 行的上面是最后一行。只需要改一处越界判断，但世界的行为会完全不同。
  • 实现几个经典图案：闪烁器（Blinker）、方块（Block）、滑翔机枪（Gosper Glider Gun）。后者会源源不断地吐出滑翔机。
  • 让用户用鼠标……目前还不行，但你可以让用户用键盘输入坐标来手动放置细胞，做一个「编辑器」。
  • 统计每一代的活细胞数，输出成一个序列。观察它有没有周期性——这就是最简单的「数据分析」。
  • 想想看：如果把「数邻居」换成「加权求和」，把「存活规则」换成「和大于阈值就激活」，你手里就有一个卷积层了。
